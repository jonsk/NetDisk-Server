# Server-com 安装与部署

> 本文只讲**从零装到能上线**；日常巡检 / 故障排查见《日常运维》，数据保护见《备份与恢复》。
> 本仓库配套脚本在 `deploy/` 下，绝大多数步骤都有现成脚本（幂等，可重复执行）。
>
> **每个步骤都有两种做法，任选其一**：**① 用脚本**（`deploy/` 下的现成脚本，幂等、推荐）——
> **② 用手工命令**（完全不带脚本，逐条敲原始命令，便于审计、逐个环节验证）。
> 两种做法最终产物一致，按你习惯选一种即可，不必两种都做。

---

## 1. 部署形态与前置要求

整个网盘是一个 **Go 单二进制**（`netdisk`），外部只有四个组件配合它：

```
Nginx(80/443) ─反代─▶ netdisk(:8080) ─▶ PostgreSQL 17 (:5432)
                                      ─▶ Redis (:6379)
```

| 组件 | 版本要求 | 装在哪 |
|---|---|---|
| netdisk | 仓库构建产物 | 本机 `/opt/netdisk/` |
| PostgreSQL | **最低 17**（见下） | 本机 |
| Redis | 7+ | 本机 |
| Nginx | 推荐 1.26+ | 本机（生产） |

> **为什么最低支持 PostgreSQL 17？**
> 主键默认值用 `gen_random_uuid()`（见迁移脚本 `00001_init.sql`）——这是 **PG 13 起内置**的 UUID 生成函数，因此版本下限不在 UUID 这条线上。本项目把最低支持定在 **PG 17**（对齐当前主流发行版自带版本），架构文档 ADR-1 也以此为准。现场若是 15/16 也能跑（gen_random_uuid 兼容），但归档/长期支持策略按 17 维护。系统当前只支持这一种数据库（不接 MySQL 等）。

## 2. 安装依赖软件

> 这一步装的是：备份工具（borg/rsync）、PostgreSQL 17、Redis、Nginx。
> 关键点：**Debian 13 系统仓库自带的就是 PostgreSQL 17**，正中本项目最低支持版本，直接装即可，**无需额外加 PGDG 源**（若现场系统仓库版本更低，如 Debian 12 自带 15，再按下方手工命令加 PGDG 装 17）。

```sh
# 交给脚本做：装 postgresql-17/redis/nginx/borg → 停用 Apache 让出 80/443
sudo bash deploy/provision/01-install-packages.sh
```

脚本会打印每个组件的版本号做确认，最后输出 `INSTALL_DONE`。

> **不依赖脚本，用手工命令一步步做**（与 `01-install-packages.sh` 等价）：

```sh
# ① 安装 PostgreSQL 17 / Redis / Nginx / 备份工具 borg
#    （Debian 13 自带 PG17，直接装；系统仓库版本过低时才需先加 PGDG 源，见下方注）
sudo apt-get update
sudo apt-get install -y postgresql-17 redis-server nginx borgbackup

# ② 停用 Apache 让出 80/443（仅当本机装了 Apache 时需要）
sudo systemctl disable --now apache2 2>/dev/null || echo '无 Apache，跳过'
```

> 脚本版把这 3 步包在一句 `sudo bash deploy/provision/01-install-packages.sh` 里，多做了「打印各组件版本号确认 + 输出 `INSTALL_DONE`」。

> 提示：PGDG 官方源在部分地区慢，可改用国内镜像
> （如 `https://mirror.nju.edu.cn/postgresql/repos/apt`）。

## 3. 系统准备（这一步在做什么）

> 目标：建一个**不让登录**的服务账号、把程序的各个目录建好并设对"属主"、生成随机口令。

```sh
sudo bash deploy/provision/02-provision-base.sh
```

具体它做了三件事（都可以对着 `ls` 结果验证）：

1. **创建服务账号 `netdisk`**：一个只用来跑服务、不能登录的账号
   （给它最小权限，程序只读二进制、写自己的数据目录）。
2. **创建目录并设属主**（最关键，属主不对会导致服务启动自检直接拒绝）：

   | 目录 | 属主 | 放什么 |
   |---|---|---|
   | `/opt/netdisk/data` | netdisk | 对象与暂存根（内容寻址对象、TUS 暂存） |
   | `/etc/netdisk` | root:netdisk | 配置文件 + secrets |
   | `/var/log/netdisk` | netdisk | 应用日志 |
   | `/var/lib/netdisk` | netdisk | 备份/演练状态 JSON |

3. **生成随机口令文件 `/etc/netdisk/secrets.env`**：一次性生成数据库口令、JWT 密钥、
   Redis 口令等（**绝不写进版本库，也绝不写进 yaml**），供后续脚本和程序读取。

> **不依赖脚本，用手工命令一步步做**（与 `02-provision-base.sh` 的 3 件事一一对应）：

```sh
# ① 创建不可登录的服务账号 netdisk（系统账号、无家目录、锁 shell）
sudo useradd --system --no-create-home --shell /usr/sbin/nologin netdisk

# ② 建目录并设属主（属主不对，服务启动自检会直接拒绝）
sudo install -d -o netdisk -g netdisk -m 0750 /opt/netdisk/data    # 对象与暂存根
sudo install -d -o root   -g netdisk -m 0750 /etc/netdisk          # 配置 + secrets
sudo install -d -o netdisk -g netdisk -m 0750 /var/log/netdisk     # 应用日志
sudo install -d -o netdisk -g netdisk -m 0750 /var/lib/netdisk     # 备份/演练状态

# ③ 生成随机口令文件 secrets.env（先取随机串，再写入，最后收紧权限）
DB_PASS=$(openssl rand -base64 24)
REDIS_PASS=$(openssl rand -base64 24)
JWT_SECRET=$(openssl rand -base64 48)
sudo tee /etc/netdisk/secrets.env >/dev/null <<EOF
NETDISK_DB_PASSWORD=$DB_PASS
NETDISK_REDIS_PASSWORD=$REDIS_PASS
NETDISK_JWT_SECRET=$JWT_SECRET
EOF
sudo chown root:netdisk /etc/netdisk/secrets.env
sudo chmod 0640 /etc/netdisk/secrets.env
```

> 字段名以程序实际读取的环境变量为准（参考 `deploy/systemd/secrets.env.example`）。
> 脚本版把这 3 步合成一句 `sudo bash deploy/provision/02-provision-base.sh`。
> 口令只生成一次；如需轮换，改这个文件然后重启服务即可。

## 4. 配置 PostgreSQL

> 这一步把 PG 调成"适合这台机器 + 安全"的状态：监听只留本机、适配小内存、
> 开 WAL 归档（时间点恢复的前提）、创建程序专用的角色和库。

```sh
sudo bash deploy/provision/03-provision-postgresql.sh
```

各项配置的目的（都写进了 `/etc/postgresql/17/main/conf.d/`）：

| 配置 | 值 | 为什么 |
|---|---|---|
| `listen_addresses` | `localhost` | 只监听本机，PG 端口**不出现在网卡上** |
| `max_connections` | 100 | 应用侧最多 32 连接，留余量给运维/psql |
| `shared_buffers` | 128MB | 小内存机适配（否则按大内存默认值会把内存吃光） |
| `archive_mode=on` + `archive_command` | — | **WAL 归档**：时间点恢复（PITR）的前提；`pg_wal` 不涨满磁盘 |
| pg_hba | 只放行回环 | 拒绝局域网直连，只能用本机访问 |

最后它还会：
- 创建角色 `netdisk` 和数据库 `netdisk`（owner=netdisk）；
- 建好 `pg_trgm` 扩展（建表脚本需要，先由超级用户建好避免迁移时权限差异）。

> **不依赖脚本，用手工命令一步步做**（与 `03-provision-postgresql.sh` 等价）：

```sh
# ① 调优 + 开 WAL 归档（写入 conf.d，避免被下次大版本升级覆盖）
sudo tee -a /etc/postgresql/17/main/conf.d/netdisk.conf >/dev/null <<'EOF'
listen_addresses = 'localhost'
max_connections = 100
shared_buffers = 128MB
archive_mode = on
archive_command = 'test ! -f /var/lib/postgresql/wal_archive/%f && cp %p /var/lib/postgresql/wal_archive/%f'
EOF
sudo install -d -o postgres -g postgres -m 0700 /var/lib/postgresql/wal_archive

# ② 创建程序专用的角色与库（口令从 §3 的 secrets.env 取）
sudo -u postgres psql <<'EOF'
CREATE ROLE netdisk LOGIN PASSWORD '<数据库口令>';
CREATE DATABASE netdisk OWNER netdisk ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;
EOF

# ③ 建 pg_trgm 扩展（由超级用户在库内建好，供迁移使用）
sudo -u postgres psql -d netdisk -c 'CREATE EXTENSION IF NOT EXISTS pg_trgm;'

# ④ 重启生效（Debian 默认 pg_hba 已只放行本机，无需额外改）
sudo systemctl restart postgresql
```

> 若现场库 locale 不是 UTF-8，请务必用第 ② 步 `TEMPLATE template0` + `LC_COLLATE 'C'` 的方式建库，保证字节序确定、贴近 Linux 生产。
> 脚本版把上面 4 步合成一句 `sudo bash deploy/provision/03-provision-postgresql.sh`（含版本/连通自检）。

## 5. 配置 Redis

> 这一步把 Redis 调成"重启不丢登录态、不会被淘汰踢人"的状态。

```sh
sudo bash deploy/provision/04-provision-redis.sh
```

Redis 里存的不是普通缓存，而是 **token / 限速窗口 / 同步游标**——丢了就相当于"所有用户被登出"。
所以有**三条硬性要求**，缺一条都会出问题：

| 要求 | 值 | 缺了会怎样 |
|---|---|---|
| 设访问口令 | `requirepass <口令>` | 登录/限速全线失效 |
| 开启持久化 AOF | `appendonly yes` + `appendfsync everysec` | 重启一次 = 全体用户被登出 |
| 禁止淘汰键 | `maxmemory-policy noeviction` | token/游标键被淘汰 = 随机把人踢下线 |

脚本还会：把监听绑到本机（`bind 127.0.0.1`）、重启后用口令实测（未认证必须被拒、认证后能 PING 通）。

> 内存上限设 96MB 是小内存机适配；到顶时因为是 `noeviction`，会**报错**而不是静默丢键——
> 报错能暴露问题，淘汰只会静默把人踢下线。

> **不依赖脚本，用手工命令一步步做**（与 `04-provision-redis.sh` 等价）：

```sh
# 三条硬性要求 + 绑本机 + 小内存上限，以追加段写入 Debian 的 Redis 配置
sudo tee -a /etc/redis/redis.conf >/dev/null <<EOF
bind 127.0.0.1
requirepass <Redis 口令>
appendonly yes
appendfsync everysec
maxmemory-policy noeviction
maxmemory 96mb
EOF
sudo systemctl restart redis-server

# 实测：未认证必须被拒、认证后能 PING 通
redis-cli -a <Redis 口令> --no-auth-warning PING   # 应返回 PONG
```

> 三条硬性要求缺一不可（见上方表格）。脚本版 `sudo bash deploy/provision/04-provision-redis.sh`
> 多做了一步重启后用口令实测（未认证必须被拒）。

## 6. 构建并部署 netdisk

### 6.1 构建（顺序很重要）

```sh
# 环境（国内加速 + 关闭校验）
export GOPROXY=https://goproxy.cn,direct GOSUMDB=off
cd Server-com
# ⚠ 管理后台前端是编译期 embed 进二进制的：改过前端必须先 pnpm build 再 go build，
#    顺序反了会嵌入旧页面（能编译、却不报错）
deploy/build-release.sh 1.0.0     # → deploy/dist/netdisk-1.0.0-linux-amd64
scp deploy/dist/netdisk-1.0.0-linux-amd64 root@<host>:/tmp/
```

> **不依赖脚本，用手工命令一步步做**（与 `build-release.sh` 等价）：
> 核心顺序不可反：**先 `pnpm build` 出前端，再 `go build`**（顺序反了会 embed 旧页面）。

```sh
# ① 环境（国内加速 + 关闭校验）
export GOPROXY=https://goproxy.cn,direct GOSUMDB=off

# ② 先构建管理后台前端（web 仓库），并把产物拷入 Server-com/internal/webui/dist（供 embed）
cd Server-com/web && pnpm install && pnpm build
# 产物就位后由 embed 指令打包进二进制（web/apps/*/dist → internal/webui/dist）

# ③ 编译服务端单二进制
cd ../ && go build -o deploy/dist/netdisk-1.0.0-linux-amd64 ./cmd/netdisk

# ④ 拷到目标机
scp deploy/dist/netdisk-1.0.0-linux-amd64 root@<host>:/tmp/
```

### 6.2 部署到目标机

```sh
sudo bash deploy/install.sh /tmp/netdisk-1.0.0-linux-amd64 http://<对外URL>
```

`install.sh` 是幂等的，会做：建用户/目录 → 生成/复用 secrets → 装二进制与配置 →
装 systemd 服务 → 自检 → 启动 → **版本自证**（成功时最后一行打印 `INSTALL_DONE`）。

> **不依赖脚本，用手工命令一步步做**（与 `install.sh` 等价，服务账号/目录/口令已由 §3 备好）：

```sh
# ① 放二进制与配置（属主必须对，自检才会过）
sudo install -o root -g netdisk -m 0755 /tmp/netdisk-1.0.0-linux-amd64 /opt/netdisk/netdisk
sudo install -o root -g netdisk -m 0644 deploy/config/config.example.yaml /etc/netdisk/config.yaml
# 若 §3 没生成 secrets 则需补一份（见 §3 ③）；已生成则复用，别覆盖

# ② 安装 systemd 单元并启动（单元内已含「自检 ExecStartPre → 迁移+启动 ExecStart」）
sudo install -o root -g root -m 0644 deploy/systemd/netdisk.service /etc/systemd/system/netdisk.service
sudo systemctl daemon-reload
sudo systemctl enable --now netdisk

# ③ 确认起来了
sudo systemctl is-active netdisk          # → active
sudo systemctl status netdisk -l --no-pager
```

> 关键点：`netdisk.service` 里的 `ExecStart=/opt/netdisk/netdisk -migrate ...` 是「先迁移再继续启动」、
> **不会退出**——手工方式下同样别把它当一次性命令去前台等待，交给 systemd 管理即可。

### 6.3 数据库迁移

迁移已写进 systemd 单元，**服务启动时自动执行**，无需手工跑：

```ini
ExecStartPre=/opt/netdisk/netdisk -check -config /etc/netdisk/config.yaml   # 启动自检
ExecStart=/opt/netdisk/netdisk -migrate -config /etc/netdisk/config.yaml    # 先迁移,再继续启动
```

> 注意：`-migrate` 的语义是"先跑迁移然后继续启动服务"，**不会退出**——
> 别在部署脚本里把它当前台命令等待，那样会永远挂住。

> **不想靠 systemd 自动迁移**、想在启动前单独执行迁移时，可用 goose 对目标库跑一次 `up`
> （迁移目录在 `internal/migrate/sql`；通常无需，启动即自动完成）：

```sh
export NETDISK_DB_DSN='postgres://netdisk:<数据库口令>@127.0.0.1:5432/netdisk?sslmode=disable'
goose -dir internal/migrate/sql postgres "$NETDISK_DB_DSN" status   # 先看版本
goose -dir internal/migrate/sql postgres "$NETDISK_DB_DSN" up        # 执行迁移
```

> 两种方式等价；只要 systemd 单元里的 `-migrate` 在，就算不手动跑 goose，启动时也会迁移。

## 7. 配置 Nginx 反向代理

> Nginx 是唯一的对外入口，netdisk 本身只监听 127.0.0.1:8080。

```sh
# apply：装站点/代理头/调优；verify：用 nginx -T（生效配置）逐条校验
sudo bash deploy/nginx/apply.sh
sudo bash deploy/nginx/verify.sh
```

**几个容易踩的坑**（脚本里已处理，这里说明原因）：
- 上传/TUS 接口必须关 `proxy_request_buffering`，否则请求体会先落 Nginx 临时盘，
  断点续传与进度都不再真实；
- 下载接口关 `proxy_buffering`，SSE 接口关 `proxy_buffering` 并把 `proxy_read_timeout` 调大。

> **不依赖脚本，用手工命令一步步做**（与 `apply.sh` + `verify.sh` 等价）：

```sh
# ① 写站点配置（最小可用，关键行已标注）
sudo tee /etc/nginx/sites-available/netdisk >/dev/null <<'EOF'
server {
    listen 80;
    server_name <对外域名>;

    # 通用反向代理：透传真实 IP
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # TUS 上传：关 request_buffering（断点续传/进度才真实）
    location /uploads/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_request_buffering off;
    }

    # WebDAV：同样关 request_buffering
    location /dav/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_request_buffering off;
        proxy_buffering off;
    }

    # SSE：关 buffering + 放宽读取超时
    location /sync/events {
        proxy_pass http://127.0.0.1:8080;
        proxy_buffering off;
        proxy_read_timeout 86400s;
    }
}
EOF

# ② 启用站点、校验语法、重载
sudo ln -sf /etc/nginx/sites-available/netdisk /etc/nginx/sites-enabled/
sudo nginx -t                                  # 语法正确才继续
sudo systemctl reload nginx

# ③ 替代 verify.sh：用「生效配置」自检关键项（不是看磁盘上的文件）
sudo nginx -T | grep -E 'proxy_(request_)?buffering|proxy_read_timeout'
```

> 手写时最容易漏的就是上面三处 `proxy_*` 缓冲设置；漏了上传/续传/SSE 会表现异常。
> 脚本版用 `deploy/nginx/verify.sh` 基于 `nginx -T` 逐条断言这些项，已替你校验。

## 8. 部署后验收

```sh
# 1) 各入口能通
curl -s -o /dev/null -w '%{http_code}\n' http://<host>/admin/    # 200「网盘管理后台」
curl -s http://127.0.0.1:8080/healthz                            # 200

# 2) 初始管理员已在"初始化数据库"时自动建立
#    用户名 admin，初始口令 admin123（首次启动前可用 NETDISK_BOOTSTRAP_ADMIN_PASSWORD 覆盖）
#    登录后请立即修改口令（推荐）：
/opt/netdisk/bin/passwd -config /etc/netdisk/config.yaml \
  -username admin -role super_admin -prompt

# 3) 端到端探针：直连应用（不要走反代——SSE 响应头会被 Nginx 消费）
/opt/netdisk/bin/probesmoke -base http://127.0.0.1:8080 -user admin -pass admin123
```
