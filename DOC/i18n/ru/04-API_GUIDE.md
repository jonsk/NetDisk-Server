# Руководство по API Server-com

> Нормативный файл: авторитетный контракт в `DOC/api/openapi.yaml` (OpenAPI v3); эта статья — его **читаемое человеком введение**.
> Связанные документы: `02-ARCHITECTURE.md` (архитектура), `05-INSTALL.md` (установка и развёртывание), `06-OPS.md` (повседневная эксплуатация), `07-BACKUP.md` (резервное копирование и восстановление)

## 1. Модель аутентификации

Служба использует **JWT (HS256)** для аутентификации; после входа выдаётся `access_token`, далее каждый запрос несёт его:

```
Authorization: Bearer <access_token>
```

**Раздельные токены по клиентам (R-14)**: токены web-клиента (панель администратора) и desktop-клиента (клиент рабочего стола) независимы друг от друга,
чтобы утечка в одном месте не затронула всё. Токен/токен обновления хранятся в Redis, поддерживается отзыв и «одиночное обновление».

| Интерфейс | Описание |
|---|---|
| `POST /api/v1/auth/login` | Вход по логину и паролю, возвращает `access_token` + `refresh_token` |
| `POST /api/v1/auth/refresh` | Обмен токена обновления на новый access-токен |
| `POST /api/v1/auth/logout` | Выход, отзыв токена |
| `GET /api/v1/me` | Информация о текущем пользователе |
| `GET /api/v1/version` | Версия серверной части |

> Сообщественная редакция сохраняет только **вход по паролю**; вход через WeCom/DingTalk/сторонний IdP удалён в сообщественной редакции.
> При превышении окна возвращается **429**, клиент должен повторить с экспоненциальной задержкой (см. §7).

## 2. Общие соглашения

- **Base URL**: `/api/v1`, в продакшене выходит наружу через единый порт Nginx.
- **Запрос/ответ**: JSON (`Content-Type: application/json`).
- **Пагинация**: списочные интерфейсы используют `limit` + `after` (keyset-курсор) для постраничной прокрутки; верхний предел `limit` — **999**
  (при превышении возвращается к значению по умолчанию 200).
- **Скачивание**: потоковый возврат + байтовый `Range` (200/206/416) + заголовки условных запросов (`If-Match`/`If-None-Match`/`If-Range`).
- **Ограничение скорости**: по семействам интерфейсов (login/upload/file_list/file_read/file_write/webdav), два окна (секунда/минута) действуют одновременно, берётся более строгое.

## 3. Группировка REST-интерфейсов

### 3.1 Файлы и каталоги

| Метод и путь | Описание |
|---|---|
| `GET /api/v1/files?space=<id>&parent_id=&limit=&after=` | Список каталога (по умолчанию 200 шт./страница; поддерживается keyset-прокрутка) |
| `POST /api/v1/files` | Создать элемент файла/каталога |
| `GET /api/v1/files/dirs` | Список каталога (специально для каталогов) |
| `GET /api/v1/files/{id}` | Детали файла/каталога |
| `GET /api/v1/files/{id}/content` | Скачать содержимое (поддерживается Range) |
| `POST /api/v1/files/{id}/move` | Переместить/переименовать |
| `POST /api/v1/files/{id}/copy` | Копировать |
| `POST /api/v1/files/{id}/share-to-space` | Копировать/шарить в другое пространство (по пути увеличения ссылки объекта +1) |
| `POST /api/v1/files/{id}/lock` | Взять/снять блокировку (объектный уровень) |
| `GET /api/v1/files/{id}/subtree-stats` | Статистика поддерева |

> Операции уровня каталога «перемещение/удаление поддерева», превышающие порог (по умолчанию 1000 строк), переводятся в **асинхронную задачу**:
> `POST` возвращает `task_id`, клиент опрашивает `GET /api/v1/tasks/{id}` для проверки прогресса.

### 3.2 Загрузка (прямая multipart-загрузка)

| Метод и путь | Описание |
|---|---|
| `POST /api/v1/upload/create` | Создать загрузку (резервирует квоту, возвращает токен загрузки) |
| `POST /api/v1/upload/simple` | Прямая multipart-загрузка (маленький файл; одна запись = финализирование) |
| `POST /api/v1/upload/{id}/finish` | Завершить/финализировать |
| `GET/PATCH /api/v1/upload/{id}` | Запрос/докачка |

> Большие файлы идут по протоколу **TUS** (см. §4).

### 3.3 Изменения и синхронизация

| Метод и путь | Описание |
|---|---|
| `GET /api/v1/changes?since=<cursor>` | Инкрементальное получение по курсору (канал «надёжный» из двух режимов) |
| `GET /api/v1/changes/head` | Получить текущий последний курсор |
| `GET /api/v1/sync/cursors` | Управление курсорами синхронизации |
| `GET /sync/events` | SSE-рассылка в реальном времени (канал «реального времени» из двух режимов) |

> Оба используют одну и ту же глобальную `change_seq`: SSE может терять кадры, но можно дозапросить по `/changes` по курсору, гарантируя отсутствие пропусков.

### 3.4 Общий доступ (шаринг)

| Метод и путь | Описание |
|---|---|
| `POST /api/v1/shares` | Создать ссылку общего доступа |
| `GET /api/v1/shares` | Список созданных мной ссылок |
| `DELETE /api/v1/shares/{id}` | Отозвать общий доступ |
| `GET /api/v1/shares/{token}/meta` | Мета-информация общего доступа (для посадочной страницы) |
| `GET /api/v1/shares/{token}/download` | Скачать по token общего доступа |

### 3.5 Пространства

| Метод и путь | Описание |
|---|---|
| `POST /api/v1/spaces` | Создать пространство (личное пространство / командное пространство) |
| `GET /api/v1/spaces/{id}` | Детали пространства (включая квоту) |
| `POST /api/v1/spaces/{id}/transfer` | Передача пространства |
| `GET /api/v1/spaces/{id}/members` | Список участников |
| `PUT/DELETE /api/v1/spaces/{id}/members/{userId}` | Добавить / удалить участника |
| `POST /api/v1/spaces/{id}/leave` | Выйти из пространства |

### 3.6 Панель администратора (только super_admin)

| Метод и путь | Описание |
|---|---|
| `POST/GET /api/v1/admin/departments` | Управление отделами |
| `PUT/DELETE /api/v1/admin/departments/{id}` | Изменение / удаление отдела |
| `POST /api/v1/admin/spaces/{id}/freeze` | Заморозить пространство (остановить синхронизацию) |
| `GET /api/v1/audit/logs` | Журнал аудита (в сообщественной редакции зарезервированная заглушка) |

> Интерфейс панели администратора для пользователей/организаций/пространств/квот предоставляется через Go `embed` (`/admin/*`).
> Также: интерфейсы управления пользователями (создание пользователя, изменение роли, настройка квоты) идут через `/api/v1/admin/*` (см. полный openapi).

## 4. TUS-загрузка фрагментами (большие файлы)

Протокол докачки для клиента рабочего стола / больших файлов (`cmd/probesmoke` в `deploy` используется как эталонная реализация):

| Шаг | Метод | Ключевые заголовки |
|---|---|---|
| Создать задачу | `POST /tus` | `Tus-Resumable: 1.0.0`, `Upload-Length`, `Upload-Metadata: filename <base64>`, `Authorization: Bearer` |
| Передать фрагмент | `PATCH /tus/{id}` | `Tus-Resumable`, `Upload-Offset`, `X-Upload-Token`, `Content-Type: application/offset+octet-stream` |
| Завершить | последний фрагмент | Ответ `200` + `Upload-Complete: true` + `X-File-Id` означает финализирование |

- **Докачка**: клиент сообщает `Upload-Offset`, сервер продолжает с этого смещения;
- **Повторное использование ticket**: тикет загрузки можно переиспользовать до финализирования, идемпотентно;
- **Уровень диска**: использование временной зоны ≥ порога (по умолчанию 90%) возвращает **507 Insufficient Storage**;
- **Сбор временных файлов**: незавершённые временные файлы собираются фоновой задачей (примерно раз в 10 минут).

## 5. WebDAV

Префикс пути `/dav/*`, основан на стандартном `x/net/webdav`, чаще всего используется для «подключения сетевого диска / проводника»:

- **PUT идёт по пути финализирования**: ≤100МБ финализируется напрямую (при превышении предлагается TUS);
- **Семантика LOCK дополнена самостоятельно** (стандартная библиотека имеет только реализацию в памяти);
- Range / условные запросы — те же, что и в REST;
- Обзор каталога отправляет несколько запросов сразу → соответственно `rate_limits.webdav` настроен шире (60/с).

## 7. Коды состояния и семантика

| Код состояния | Семантика | Описание |
|---|---|---|
| 200 / 201 | Успех | Успешное финализирование несёт `X-File-Id` |
| 206 / 416 | Частичное содержимое / выход за пределы диапазона | Range скачивания |
| 400 / 422 | Ошибка параметра | Сбой валидации |
| 401 | Не аутентифицирован | Токен отсутствует/просрочен |
| 403 / 401 | Ограничение прав | **Приостановить синхронизацию этого пространства, никогда не удалять локально** (поведение клиента) |
| 404 / 410 | Не существует / удалено | 410 = объект/пространство перенесено или удалено |
| 409 | Конфликт | Конфликт версий, повтор имени (проверка без учёта регистра) |
| 429 | Ограничение скорости | Нужна повторная попытка с задержкой |
| 500 | Ошибка сервера | См. обработку сбоев в документе по эксплуатации |
| 507 | Недостаточно места для хранения | Уровень диска достиг порога |

**Обработка клиентом 429**: опыт проекта — «повтор с задержкой при 429 обязателен» — при фактической очистке зонд-файлов
`DELETE` натыкался на ограничение `file_write`, без задержки происходило бы **тихое недоудаление**; при создании задачи загрузки натыкание на лимит без задержки проявляется как «файл никогда не загружается».

## 8. Связь с нормативным файлом

- Эта статья — читаемое человеком введение; **авторитетный контракт** — машиночитаемый `DOC/api/openapi.yaml`.
- Репозиторий web выполняет на его основе проверку контракта фронтенда (`pnpm check:api`); desktop-сторона использует gen-csharp для генерации клиентского кода.
- При изменении контракта у `web` и `desktop` есть по одной vendored-копии, требуется **синхронизация в трёх местах**.
