## II. Что предоставляет система извне

Server-com — это **бэкенд корпоративного сетевого диска**, предоставляющий извне четыре типа возможностей, через которые клиенты (панель администратора / десктоп / инструменты файловых протоколов) управляют сетевым диском:

| Возможность | Описание | Внешний вид |
|---|---|---|
| **REST интерфейс** | вход, CRUD файлов, скачивание, общий доступ, управление панелью и т.д. | `/api/v1/*` |
| **TUS возобновляемая загрузка** | загрузка больших файлов по фрагментам, возобновление при обрыве сети | `/tus/*` |
| **WebDAV** | совместимость со стандартным файловым протоколом, прямое монтирование как сетевой диск | `/webdav/*` |
| **SSE синхронизация реального времени** | при изменении файла — push клиенту, затем инкрементальная выборка | `/api/v1/events` |

## III. Список функциональных модулей

### 1) Учётные записи и аутентификация

- **Вход по логину/паролю**: вход по имени пользователя/паролю, поддержка продления refresh token, выхода.
- **Механизм токенов**: после успешного входа выдаётся access token; токены разделены по эндпоинтам (панель / десктоп), возможности токенов разных эндпоинтов изолированы.
- **Управление учётными записями**: панель может создавать пользователей, включать/отключать учётные записи, менять роли; поддерживается детальное управление ролями загрузки/скачивания.
- **Безопасность паролей**: строгая проверка паролей и хранение хэша; при неудачных попытках — временная блокировка против brute-force.

### 2) Организация и пространства

- **Организационная структура**: поддержка обслуживания дерева отделов (добавление/удаление/изменение отделов, просмотр поддеревьев, перестроение замыкания); отдел — один из входов прав доступа.
- **Пространства**: у каждого пользователя есть личное пространство; можно создать командное пространство и пригласить участников для совместной работы.
- **Управление участниками**: добавление/удаление участников пространства, изменение ролей, передача, роспуск; администратор может глобально управлять пространством (квоты, заморозка, изъятие).

### 3) Управление файлами

- **Операции с метаданными**: просмотр файлов/каталогов, создание каталогов, переименование, перемещение, удаление.
- **Скачивание**: поддержка потокового скачивания, HTTP Range докачки, условных запросов (If-Match и др., оптимистичная блокировка).
- **Мгновенная загрузка**: файлы с одинаковым содержимым пропускают повторную загрузку, повторно используя уже сохранённый объект.
- **Блокировка редактирования**: файл можно заблокировать, чтобы избежать взаимного перезаписывания при одновременном редактировании несколькими людьми.
- **Ограничения имён и путей**: легитимность имён файлов, длина пути, глубина каталога и т.д. единообразно проверяются сервером.
- **Квоты**: управление квотами пространства, перехват при превышении; со сверкой квот и оповещением о дрейфе.

### 4) Загрузка и запись

- **TUS возобновляемая загрузка**: загрузка больших файлов фрагментами, поддержка возобновления при прерывании, параллельных фрагментов.
- **Единый путь записи**: все загрузки (фрагменты, запись WebDAV на диск) в итоге сходятся в один вход финализирования (finalize), гарантируя «у одного файла только один источник записи», естественно избегая конкурентной перезаписи.
- **Хранилище, адресуемое по содержимому**: файлы хранятся по хэшу содержимого, одинаковое содержимое хранится в одном экземпляре (дедупликация).
- **Жизненный цикл**: объект имеет явный переход состояний от записи до «удаляемый/утилизируемый», избегая случайного удаления файла в процессе.

### 5) WebDAV и совместное использование

- **WebDAV**: предоставляет чтение/запись файлов, операции с каталогами, копирование/перемещение, блокировку и т.д. по стандартному протоколу WebDAV, совместимо с десктопным монтированием.
- **Ссылки общего доступа**: файл/каталог может генерировать ссылку общего доступа (доступ/скачивание без входа), это единственный выход системы без входа; можно установить срок действия или отозвать в любое время.

### 6) Синхронизация реального времени

- **SSE push**: при изменении файла в реальном времени через долгое соединение push онлайн-клиентам.
- **Инкрементальная выборка**: клиент выбирает изменения курсором инкрементально; даже при потере push итоговая согласованность не нарушается (выборка — авторитетный путь).
- Сценарий применения: двусторонняя синхронизация каталога десктопа с облаком.

### 7) Панель администратора и безопасность

- **Панель администратора**: `/admin` предоставляет страницу управления (пользователи, организация, управление пространствами).
- **Контроль доступа**: токен эндпоинта `web` ограничивает доступ к панели; токены H5/десктоп не могут зайти в панель.
- **Ограничение скорости**: семейства интерфейсов входа, загрузки, чтения файлов имеют независимый rate limit, формируя двухслойную защиту с Nginx; защита от brute-force и спама интерфейсами.

### 8) Хранилище и эксплуатация

- **Патруль объектов**: панель периодически сканирует диск, обнаруживая утечки объектов (мусор без ссылок) и обратных сирот (ссылки без файлов).
- **Сверка квот**: периодическое сравнение «логического объёма vs фактического занимаемого», при слишком большом дрейфе — оповещение и возможная автоматическая обратная запись исправления.
- **Форма развёртывания**: один бинарный файл + systemd + Nginx; скрипты резервного копирования/восстановления, проверки поставляются с репозиторием.
- **Форма хранилища**: по умолчанию локальный диск (адресуемый по содержимому); только локальное хранилище, без backend сторонних объектных хранилищ.

## IV. Форма развёртывания и запуска

- **Один бинарный файл**: весь сервис компилируется в один исполняемый файл, управляется systemd; Nginx выполняет обратное проксирование и HTTPS.
- **Предварительные зависимости**: PostgreSQL 17 + Redis (зависимость аутентификации/rate limit, при недоступности не запускается).
- **Конфигурация**: yaml файл + переменные окружения; пароли/ключи передаются только через переменные окружения, никогда не записываются в yaml или в репозиторий.
- **Миграция БД**: сервис содержит скрипты миграции, выполняемые автоматически при развёртывании.
- **Фронтенд панели администратора**: уже embed в бинарный файл, отдельное развёртывание каталога фронтенда не требуется.
